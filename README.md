# جاكوم (Jackom)

لعبة جماعية اجتماعية تُلعب عبر جهاز مضيف (تلفزيون/شاشة رئيسية) وهواتف اللاعبين، مبنية على خادم واحد يملك الحقيقة الكاملة لحالة الغرفة (`RoomState`) عبر Redis، وآلة حالات محدودة (FSM) صريحة تتحكم بدورة اللعب من غرفة الانتظار وحتى النتائج النهائية. اللاعبون يرسلون نوايا (`intents`) فقط، والخادم هو من يقرر ما هو مسموح ويبني العروض (views) الخاصة بكل طرف.

> هذا مستودع عمل داخلي قيد التطوير النشط — راجع [`IMPLEMENTATION_PROGRESS.md`](IMPLEMENTATION_PROGRESS.md) للحصول على السجل الكامل والمفصّل لكل خطوة تم إنجازها.

---

## نظرة عامة على المفهوم

- غرفة واحدة تُدار بالكامل من الخادم؛ لا يوجد أي منطق لعبة على العميل.
- جهاز "المضيف" (Host) ينشئ الغرفة ويُعرض شاشة TV مشتركة، بينما ينضم اللاعبون من هواتفهم عبر رمز الغرفة.
- كل جولة تتضمن اختيار لعبة مصغّرة (mini-game)، فرصة "اختراق" سرية لأحد اللاعبين المخصصين كـ"هاكرز"، تصويت جماعي، وإعلان نتائج — مع لعبة سابعة خاصة (Special Game) تُدرج بين الجولات حسب قواعد قابلة للتهيئة.
- كل تفاصيل التصميم والقواعد النهائية موثقة في:
  - [`ARCHITECTURE.md`](ARCHITECTURE.md) — آلة الحالات الكاملة، نموذج الجلسات (host/player)، هيكل بيانات Redis، وحدود العرض (views).
  - [`GAMEPLAY_RULES_V1.md`](GAMEPLAY_RULES_V1.md) — قواعد اللعب النهائية.
  - [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md) — هوية جاكوم البصرية.

## بنية المستودع (Monorepo)

```
jackom/
├── apps/
│   ├── server/          # خادم Node.js/TypeScript: FSM + Redis + WebSocket gateway + HTTP API
│   │   ├── src/
│   │   │   ├── fsm/           # آلة الحالات: transitions, guards, durations, match-clock
│   │   │   ├── gateway/       # خادم WebSocket، مصادقة الاتصال، تحقق الرسائل، معدل الإرسال
│   │   │   ├── http/          # واجهة HTTP لإنشاء/الانضمام إلى الغرف
│   │   │   ├── actors/        # RoomActor: طابور معالجة متسلسل لكل غرفة
│   │   │   ├── persistence/   # طبقة تجريد Redis (KeyValueStore + مستودعات typed)
│   │   │   ├── timers/        # جدولة المؤقتات من جهة الخادم واستعادتها بعد إعادة التشغيل
│   │   │   ├── minigames/     # الألعاب المصغّرة الست + Bomb Protocol (اللعبة الخاصة)
│   │   │   ├── rules/         # سجلّات القواعد القابلة للتهيئة (rule-id registries)
│   │   │   ├── views/         # بناء TvView / PlayerView من RoomState (بدون تسريب بيانات خاصة)
│   │   │   └── db/            # طبقة PostgreSQL عبر Prisma (حسابات، ملكية الألعاب)
│   │   └── test/              # اختبارات Vitest شاملة لكل ما سبق
│   └── web/              # واجهة Next.js (React 19) + Tailwind، عربي RTL بالكامل
│       ├── app/                # صفحات ولوحات (لوبي، تسجيل دخول، تسجيل، اختبار)
│       ├── components/         # مكوّنات الواجهة (gameplay, auth, quiz, graphics)
│       └── lib/                # عميل WebSocket، منطق اللعب على العميل، مصادقة
├── packages/
│   └── shared-types/     # أنواع TypeScript مشتركة بين الخادم والواجهة (قابلة للتسلسل JSON)
├── docker-compose.dev.yml   # Redis + PostgreSQL محليًا للتطوير فقط
├── ARCHITECTURE.md           # التصميم المرجعي الكامل (المصدر الأساسي للحقيقة المعمارية)
└── IMPLEMENTATION_PROGRESS.md  # سجل تفصيلي بكل خطوة تطوير أُنجزت وقراراتها
```

## المبادئ المعمارية الأساسية

مأخوذة من [`ARCHITECTURE.md`](ARCHITECTURE.md) وتنعكس مباشرة في الكود:

1. **الخادم هو المصدر الوحيد للحقيقة** — العملاء لا يستقبلون أبدًا `RoomState` الخام، بل عروضًا (views) مُشتقة حسب دور كل طرف.
2. **العملاء يرسلون نوايا لا حالة** — كل حدث من اللاعب يحمل `{phaseId, seq, actionId, type, payload}`؛ الهوية تُربط عند اتصال WebSocket نفسه وليس من داخل الرسالة، فلا يمكن انتحال هوية لاعب آخر.
3. **آلة حالات صريحة واحدة**، تحويلاتها دالة نقية `(state, event) -> state`، تُنفَّذ داخل طابور معالجة متسلسل لكل غرفة (`RoomActor`) لمنع أي تسابق (race) بين حدثين لنفس الغرفة.
4. **البيانات الخاصة لا تصل أبدًا لأي بث عام** — هذا مفروض هيكليًا: نوع البيانات المسموح ببثها (`TvView`/`PlayerView`) لا يملك أصلًا حقلاً يحمل دورًا أو خيار اختراق أو محتوى تصويت.
5. **المؤقتات طابع زمني بداية + مدة**، لا عدّاد نازل حي — الخادم يملك الموعد النهائي وتأثير انتهائه، والعميل يعرض عدّادًا محليًا فقط.
6. **كل لعبة مصغّرة هي إضافة (plugin)** تتوافق مع واجهة `MiniGameModule` واحدة، وليست حالة مدمجة في الـFSM.
7. **لا شيء يُبرمج بشكل ثابت مما لم يُحسم بعد** — عدد الهاكرز، تأثير الاختراق، توقيت اللعبة الخاصة، إلخ، كلها قيم تهيئة (config) بمعرّفات قواعد (`rule-id`) قابلة للاستبدال دون تعديل الـFSM.

## الحزمة التقنية (Tech Stack)

| الطبقة | التقنية |
|---|---|
| الخادم | Node.js, TypeScript (strict mode), `ws` (WebSocket)، HTTP API مخصّص |
| التخزين اللحظي | Redis (عبر `ioredis`) — حالة الغرفة، الجلسات، أكواد الغرف |
| التخزين الدائم | PostgreSQL عبر Prisma — الحسابات، ملكية الألعاب، الجلسات طويلة الأمد |
| التحقق من البيانات | Zod — لكل رسالة WebSocket ووثيقة مخزّنة في Redis |
| الواجهة | Next.js 16 (App Router)، React 19، Tailwind CSS 4، دعم RTL عربي كامل |
| الاختبارات | Vitest (خادم وواجهة)، Playwright (اختبارات E2E) |
| الحاويات (تطوير فقط) | Docker Compose (Redis + PostgreSQL محليًا) |

## البدء السريع (تطوير محلي)

الدليل الكامل والمفصّل موجود في [`LOCAL_DEVELOPMENT.md`](LOCAL_DEVELOPMENT.md) (مكتوب لمن ليس لديه خبرة سابقة بـDocker/Redis). ملخص سريع:

```bash
# 1. تثبيت الاعتماديات (يوجد node_modules منفصل للواجهة)
npm install
npm install --prefix apps/web

# 2. تشغيل Redis و PostgreSQL محليًا عبر Docker
npm run dev:services

# 3. نسخ ملفات البيئة
cp apps/server/.env.example apps/server/.env

# 4. تشغيل الخادم والواجهة معًا
npm run dev
```

- الخادم: `http://localhost:4000` (HTTP API) و `ws://localhost:4001` (WebSocket gateway)
- الواجهة: `http://localhost:3000`

### أوامر مفيدة أخرى

```bash
npm run typecheck        # فحص TypeScript الصارم للخادم + الحزم المشتركة + الواجهة
npm test                 # تشغيل كل اختبارات Vitest (خادم + واجهة)
npm run dev:server       # الخادم فقط (tsx watch)
npm run dev:web          # الواجهة فقط (Next.js dev)
npm run db:migrate       # تطبيق ترحيلات Prisma على قاعدة بيانات التطوير
```

> **ملاحظة:** المشروع لا يعمل بدون Redis — لا يوجد بديل صامت في الذاكرة إلا داخل مجموعة الاختبارات الآلية فقط.

## حالة المشروع

آخر نقطة تطوير موثّقة: **إغلاق حلقة اللعب الكاملة (Full Gameplay Closure)** — الست ألعاب مصغّرة العادية بالإضافة إلى اللعبة الخاصة (Bomb Protocol) تعمل من طرف إلى طرف عبر الخادم والواجهة، مدعومة بمجموعة اختبارات واسعة. للتفاصيل الكاملة لكل خطوة (الأنواع المشتركة، آلة الحالات، Redis، بوابة WebSocket، المؤقتات، الواجهة، القاعدة الخلفية الدائمة، الألعاب المصغّرة) راجع [`IMPLEMENTATION_PROGRESS.md`](IMPLEMENTATION_PROGRESS.md).

تقارير تدقيق ومراجعة إضافية موجودة في جذر المستودع (`*_REPORT.md`, `*_AUDIT.md`) توثّق جلسات تدقيق وظيفي وأمني منفصلة.

## الأمان

- لا يُخزَّن أي سرّ فعلي في المستودع — `apps/server/.env.example` يحوي قيمًا محلية وهمية فقط (`.env` الفعلي مُستبعد عبر `.gitignore`).
- جميع خدمات Docker المحلية (Redis, PostgreSQL) مربوطة بـ `127.0.0.1` فقط ولا يمكن الوصول إليها من خارج الجهاز.
- رموز الجلسات (session tokens) تُهاش (HMAC) قبل تخزينها، ولا تُسجَّل أبدًا في أي log.
